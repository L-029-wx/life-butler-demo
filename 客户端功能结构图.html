一
设备管理
25 项 · 4 必做 · 8 扩展

把「厂家各异的存量设备」变成「可分析的统一数据源」——设备接入时声明能力，平台映射到统一指标域

1.1 接入与发现
  • 扫码配网（Wi-Fi / Zigbee / 蓝牙 Mesh）
  • 局域网自动发现
  • 手动添加（按数据能力归类）
  • 设备能力声明 → 统一指标域映射★
  • 第三方平台账号绑定（米家 / 涂鸦 / HomeKit）◆
1.2 设备清单
  • 按房间视图（对应平面图 9 个空间）
  • 按类型视图
  • 在线 / 离线 / 信号强度
  • 电池电量（门磁 / 传感器）
  • 计量点命名与用途标注◆
1.3 红外转发
  • 码库匹配（空调 / 电视 / 机顶盒 / 浴霸 / 晾衣架）★
  • 遥控学习
  • 按房间配置（红外不能穿墙，一间一个）★
  • 遥控动作回传成事件 → 与功率曲线交叉验证★
1.4 自动化与场景
  • 离家自动关机（门磁 + 人体存在双确认）◆
  • 夜间策略（照明 / 空调）
  • 峰谷错峰（可延后负载）
  • 可视化规则编辑器◆
1.5 设备健康
  • 安全使用年限到期提醒（国标：冰箱空调 10 年 / 其余 8 年）
  • 功率曲线异常（启停周期变化）
  • 计量校准◆
  • 固件与网关管理
1.6 数据质量
  • 离线补数◆
  • 异常读数标记（不参与基线）◆
  • 数据保留策略◆
二
宠物
16 项 · 5 必做 · 9 扩展

宠物照护是竞品普遍只做「投喂提醒」的浅水区；本项目把排泄称重纳入，使照护从「记得喂」推进到「看得见身体状态」

2.1 宠物档案
  • 品种 / 年龄 / 体重 / 绝育 / 疫苗
  • 多宠物分档管理◆
2.2 投喂与饮水
  • 投喂次数与时段
  • 缺次提醒（低于基线众数即推送）★
  • 饮水量监测◆
2.3 排泄称重
  • 排泄位置称量插件★
  • 每次排泄量曲线★
  • 频次统计（日 / 周）★
  • 与进食、饮水量做关联分析◆
  • 异常提示（频次突增/骤减、单次量偏离）—— 只报事实、不下诊断★
  • 猫砂盆清洁提醒◆
2.4 活动与陪伴
  • 独处时长（人体存在 + 门磁 → 家中无人时段）◆
  • 活动区域分布◆
  • 互动频次◆
2.5 照护日历
  • 驱虫 / 疫苗 / 体检提醒◆
  • 宠物照护周报◆
三
健康检测
18 项 · 8 必做 · 7 扩展

全屋不装摄像头，人体存在一律用毫米波雷达 —— 用「非侵入式」换「长辈愿意用」

3.1 作息与睡眠
  • 入睡 / 起床基线（工作日与周末双模式）
  • 夜间离床次数与时长★
  • 睡眠环境（温湿度）
3.2 活动与久坐
  • 房间级活动轨迹（毫米波雷达，不采集图像）★
  • 久坐提醒◆
  • 日活动量趋势◆
3.3 如厕与洗浴
  • 时长基线★
  • 夜间异常滞留关注（只报事实，不贴标签）★
  • 家属关注提醒★
3.4 室内环境健康
  • 温湿度
  • 空气质量（PM2.5 / CO₂）◆
  • 通风提示（结合门窗开合）◆
3.5 长辈关怀

  • 全屋不装摄像头★
  • 不采集生物特征★
  • 健康数据分级授权◆

客户端在系统中的位置

客户端App · 小程序 · 音箱 · Web（本图即此层）
服务层基线引擎 · 判断与建议层 · 传达层（人格渲染）
数据层Hive 四层数仓：ODS → DWD → DWS（宽表）→ ADS
采集层28 个点位：计量插座 · 门磁 · 毫米波雷达 · 温湿度 · 红外转发
设计说明 · 三条贯穿原则
① 判定与表达分离：结论由可解释算法给出（可回溯），大模型只负责把结论说成人话 —— 所以「基础设置」里 AI 与算法是分开的两块，不是一块。
② 能力声明式接入：存量设备厂家各异，设备接入时声明自己能提供哪些字段，平台映射到统一指标域 —— 这是「设备管理」里那条 ★ 的由来。
③ 非侵入式换接受度：健康检测全程不用摄像头、不采生物特征，用毫米波雷达；隐私边界是写在设置里可查的，不是一句口号。
